# weekly — 주간 작업 요약

Claude Code: `/weekly` · Codex: `$weekly` — 둘 다 **이 저장소(wf) 루트에서** 연 세션에서 쓴다.

며칠 범위의 커밋을 읽어 **사내 보고용 주간 요약 + 그 기간의 진척도**를 대화에 출력한다. 독자·선별·주제 묶기·내부 이름 번역·출력 형식은 전부 **`daily` 스킬(`.agents/skills/daily/SKILL.md`)의 규칙을 그대로 따른다** — 이 파일은 그 위에 얹는 차이만 적는다. daily 를 읽지 않았으면 먼저 읽는다.

## 범위 정하기

사용자의 말을 `wf daily` 범위 인자로 바꾼다. 애매하면 **이번 주**로 잡고 어떤 범위를 썼는지 첫 줄에 밝힌다.

| 사용자의 말 | 인자 | 뜻 |
| --- | --- | --- |
| 이번 주, 주간 보고 (기본) | `week` | 이번 주 월요일 ~ 오늘 |
| 지난주 | `lastweek` | 지난주 월 ~ 일 |
| 최근 일주일 | `-7..today` | 7일 전 ~ 오늘 |
| 마지막 보고 이후, 밀린 것 | `last` | `progress.md` 최신 섹션 다음 날 ~ 오늘 |
| 이달, 월간 | `month` | 이달 1일 ~ 오늘 |
| 날짜를 직접 말함 | `YYYY-MM-DD..YYYY-MM-DD` | |

```bash
node wf.js daily week
node wf.js progress done week     # 같은 범위에서 100% 가 된 항목
```

**보고일은 범위의 끝 날짜다.** `wf daily` 가 만드는 진척도 섹션도, 아래 `progress set --date=` 도 그 날짜를 쓴다.

## daily 와 다른 점

**압축을 한 단계 더 한다.** 하루치는 "무엇을 했나" 지만 한 주치는 "무엇이 됐나" 다.

- 주제는 **제품 단위**로 세운다(`## 웹 관리자`, `## 회사 홈페이지`). 한 제품 안에서 작업 영역이 뚜렷이 갈리면 `## 웹 관리자 — 설정 화면` 처럼 나눠도 되지만, 제품당 보통 1 ~ 2개다.
- 항목은 **결과**로 쓴다. 같은 화면을 월·화·수에 걸쳐 만들었으면 "OO 화면 구현(목록·상세·결제)" 한 줄이지, 날짜별 세 줄이 아니다. 한 주제에 2 ~ 5개.
- 주 중에 넣었다 뺀 것, 고쳤다 다시 고친 것은 **주말 기준 순변화**만 남긴다. daily 의 "같은 회차 안 순변화" 규칙을 한 주로 넓힌 것이다.
- 숫자는 주 단위로 합친다("회귀 테스트 25 → 41건", "화면 4개 구현"). 커밋 수·라인 수는 쓰지 않는다 — 독자에게 의미 없다.
- 날짜·요일을 항목에 적지 않는다. 언제 했는지가 아니라 무엇이 됐는지를 보고하는 글이다.

**완료 항목을 앞세운다.** `node wf.js progress done <같은 범위>` 로 그 기간에 100% 가 된 진척도 항목을 얻어, 요약 맨 앞에 `## 완료` 주제로 둔다(항목 이름은 진척도 제목 그대로, 한 줄에 하나). 완료가 없으면 이 주제를 만들지 않는다. 그 다음에 제품별 주제가 온다.

**진척도 갱신은 daily 와 같다** — 범위 끝 날짜를 보고일로 `set --date=<보고일>`. 단, 매일 `daily` 를 돌린 주라면 진척도는 이미 최신이므로 커밋과 어긋나는 항목만 손본다. 갱신 뒤 `node wf.js progress --date=<보고일>` 을 다시 읽어 `---` 아래에 그대로 붙이는 것도 같다.

## 출력

```
(범위: 2026-09-08 ~ 2026-09-12)

## 완료

회사 홈페이지 - 사이트 내용 수정

## 웹 관리자

설정 화면 구현 — 목록·상세·결제 3개 화면, 재설계안 반영
차단 규칙 회귀 테스트 25 → 41건으로 확대

## 개발 환경 정비

민감정보 유출 차단 검사의 우회 구멍 3건 차단
CI 검사 순서를 조정해 빌드 전에 문제를 잡도록 변경

---

웹 관리자 - 설정 화면 - 70%
개발 환경 정비 - 민감정보 차단·자동 검사 - 90%
```

첫 줄의 `(범위: ...)` 는 어떤 기간을 정리했는지 독자와 사용자가 같이 보라고 두는 것이다. 나머지 형식(목록 기호 없음, 항목 사이 빈 줄 없음, 명사형 종결, 진척도는 한 글자도 바꾸지 않음)은 daily 와 같다.

커밋이 0개면 그 사실만 알리고 멈춘다. 수집 실패·fetch 실패가 있으면 daily 와 같이 어느 저장소가 빠졌는지 맨 앞에 알린다.
